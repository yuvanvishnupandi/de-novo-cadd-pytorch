# EUREKA: Comprehensive Project Overview (70-80% Complete Phase)

## 1. Project Introduction
**EUREKA** is a Multi-Criteria Drug Discovery Pipeline. It aims to accelerate pharmaceutical research by generating novel (*De Novo*) chemical molecules and rigorously filtering them through AI-driven criteria to identify safe and viable drug candidates.

This project strictly employs **Generative AI (Deep Learning) and Machine Learning**. It explicitly **avoids Agentic AI**, using a deterministic, rule-based pipeline that guarantees repeatable, safe, and controlled execution.

The current implementation represents 70-80% of the entire project scope. The entire Backend architecture (Data Pipelines, AI Models, Physics Simulation, and Master Pipeline) is complete, tested, and operational. The remaining 20-30% comprises the React Frontend Dashboard and Cloud Hosting, which will be implemented in the final phase.

## 2. Architecture & File Structure Explained
The backend is modularized into dedicated packages. Here is the complete breakdown of every folder and file currently working in the project:

### 📂 `eureka/backend/data/` (The Datasets)
This folder holds all the raw and processed data required by our AI models.
- **`zinc_smiles.csv`**: Contains 500,000 SMILES strings from the ZINC database. This massive dataset teaches our GenAI the "grammar" of valid chemical structures.
- **`chembl_target_data.csv`**: Raw IC50 bioactivity data (263 molecules) downloaded directly from the ChEMBL database for our default target (COVID-19 3CL Protease).
- **`chembl_cleaned_pubchem.csv`**: The refined version of the ChEMBL data, enriched with features (MW, LogP, HBD, HBA) pulled live from the PubChem API. This is the training data for our Bioactivity model.
- **`tox21.csv`**: Contains toxicity data for ~8,000 molecules. Used to train our AI to recognize and filter out poisonous compounds.
- **`6lu7_target.pdb`**: The 3D protein structure of the COVID-19 target, downloaded from the RCSB PDB for physics simulations.
- **`pipeline_results.csv`**: The final output file generated by the pipeline, containing the approved drug candidates.

### 📂 `eureka/backend/data_pipelines/` (Data Engineering)
Scripts that handle data ingestion, cleaning, and feature extraction.
- **`data_ingestion.py`**: Connects to the ChEMBL database API to download raw bioactivity data for a specific disease target.
- **`data_preprocessing.py`**: Connects to the PubChem API. It takes raw chemical SMILES strings, cleans them, and extracts the 4 critical Lipinski features: Molecular Weight, LogP (lipophilicity), Hydrogen Bond Donors, and Acceptors.
- **`tox21_preprocessing.py`**: Cleans the Tox21 dataset and trains the Random Forest classifier that detects toxicity.
- **`__init__.py`**: Makes this folder a standard Python package.

### 📂 `eureka/backend/ai_models/` (The Brain)
Contains the Generative AI and Machine Learning models.
- **`genai_model.py`**: Defines the Deep Learning architecture. We use a **Long Short-Term Memory (LSTM)** Neural Network (a foundational NLP/DL model). It maps characters to vectors and builds the neural structure.
- **`train_genai.py`**: The heavy-duty training script. It loads the 500k ZINC molecules and trains the LSTM on a GPU to learn how to generate real chemical strings. It also demonstrates **Prompt Engineering** via Temperature Scaling.
- **`model_training.py`**: Trains our Machine Learning **Random Forest Classifier** on the ChEMBL data to predict whether a new molecule will be biologically active against the target.
- **`__init__.py`**: Makes this folder a standard Python package.

### 📂 `eureka/backend/external_tools/` (Physics & Validation)
- **`run_vina.py`**: Interfaces with AutoDock Vina, RDKit, and Meeko. This script performs 3D molecular docking, simulating how the generated drug physically binds to the disease protein to calculate binding affinity (kcal/mol).
- **`__init__.py`**: Makes this folder a standard Python package.

### 📂 `eureka/backend/` (Core Orchestration)
- **`pipeline_manager.py`**: The master deterministic orchestrator. It executes the pipeline in a strict, linear order: 
  1. Generate molecules via GenAI.
  2. Fetch features via PubChem.
  3. Grade Bioactivity (ML).
  4. Grade Toxicity (ML).
  5. Run 3D Physics Simulation.
  *(Note: It includes rule-based fallbacks (Lipinski Rules) if Application Control Policies block DLLs on university laptops).*
- **`main.py`**: A FastAPI web server that opens API endpoints so the future React Frontend can trigger the pipeline.
- **`prompt_engineering_demo.py`**: A dedicated script to demonstrate **Temperature Scaling** as a form of Prompt Engineering, controlling how creative or conservative the AI's generated molecules are.
- **`requirements.txt`**: Lists every Python library required to run the project.

## 3. Addressing the Review Objectives

### A. Justification on ML/DL/NLP/Transformer (GenAI Concepts)
This project is built purely on Machine Learning and Deep Learning NLP concepts. 
- **DL/NLP:** By treating SMILES strings (e.g., `CC(=O)OC1=CC=CC=C1C(=O)O`) as a language, we use an **LSTM Neural Network** to perform sequence generation. The AI learns chemical syntax and semantics to generate *De Novo* molecules.
- **ML:** We use **Random Forest Classifiers** as our grading mechanism. This acts as our Multi-Criteria Validation layer, intelligently filtering out inactive or toxic compounds generated by the GenAI.
- **No Agentic AI:** The flow of data through `pipeline_manager.py` is entirely deterministic. The AI does not make autonomous decisions about the pipeline flow.

### B. Generated Content and Analysis Link with Objectives
The core objective is to discover viable drugs. The `pipeline_manager.py` script proves this loop is closed:
1. It generates novel chemical content.
2. It analyzes the content dynamically by pulling real-world chemical features from PubChem.
3. It passes the data through the ML graders.
4. It outputs only the approved, validated molecules.

### C. Prompt Engineering Usage on Use Case Scenarios
In generative models for text/sequences, Prompt Engineering is implemented through **Temperature Scaling**. 
- A low temperature (e.g., 0.1) prompts the AI to act conservatively, producing highly stable, repetitive variations of known scaffolds. (Use case: Minor optimization of a known drug).
- A high temperature (e.g., 2.0) prompts the AI to hallucinate and be highly creative, generating wild, never-before-seen structures. (Use case: Discovering completely novel drug classes).
Our `prompt_engineering_demo.py` explicitly demonstrates this control mechanism in action.
